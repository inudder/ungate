# Service CLI берётся из Beta-пакета и хранится в профиле Beta

Лаунчер гоняет `codex.exe` (service CLI) для plugin store, MCP-инвентаря и каталога
моделей. Этот бинарь должен принадлежать тому MSIX-пакету, который запускается: версия
задаёт формат plugin store и набор CLI-подкоманд, а извлечённые экземпляры в общем
`%LOCALAPPDATA%\OpenAI\Codex\bin` переписываются приложениями и исчезают. Поэтому
лаунчер держит собственную копию CLI Beta-пакета в профиле Beta
(`<beta-home>/.launcher-cli/<package-version>/`), сверяя её SHA-256 с эталоном из
`app/resources` пакета, и обновляет копию только при смене версии пакета.

## Considered Options

- Копировать CLI Beta-пакета в репозиторий лаунчера — отвергнуто: бинарник на 358 МБ не
  место в репозитории, и копия устаревает отдельно от пакета.
- Использовать извлечённый экземпляр из общего `bin` — отвергнуто: оба MSIX-пакета
  делят этот каталог и подчищают чужие папки, поэтому нужный бинарь может исчезнуть
  между запусками.
- Запускать `codex.exe` прямо из `WindowsApps` — невозможно: процесс получает
  `Access is denied`, этот бинарь исполняется только из пакета.

## Consequences

- Service CLI всегда совпадает по версии с приложением, которое читает подготовленный
  профиль; plugin store и каталог моделей не расходятся по формату.
- Копия обновляется при смене версии пакета и занимает место в профиле; при неудачном
  копировании лаунчер продолжает без service-CLI задач и предупреждает.
