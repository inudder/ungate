# Graphify — полная инструкция для AI-агентов

> Краткое обязательное ядро этих правил продублировано в `AGENTS.md` и действует всегда.
> Этот файл — расширенная справка: детали команд, политика backend, верификация, типовые проблемы.
> Не нужно читать его целиком в начале каждой сессии — открывай нужный раздел по задаче.

---

## 1. Артефакты Graphify

Проект индексируется Graphify. Все артефакты лежат в `graphify-out/`:

| Файл | Назначение |
| --- | --- |
| `graph.json` | полный граф знаний; источник для `query` / `path` / `explain` и MCP-сервера |
| `GRAPH_REPORT.md` | обзор: god nodes, сообщества, неожиданные связи, предлагаемые вопросы |
| `graph.html` | интерактивная визуализация для человека; агенту обычно не нужна |
| `wiki/index.md` | markdown-wiki по подсистемам (если генерировалась через `--wiki`) |
| `manifest.json` | отпечатки файлов для инкрементального обновления; portable, его можно коммитить |
| `cache/` | кэш извлечения; коммитить необязательно (ускоряет rebuild, раздувает репо) |

Каждое ребро графа несёт тег достоверности:

- `EXTRACTED` — связь явно извлечена из AST/текста. Это сильный сигнал, но не доказательство runtime-поведения и не замена чтению кода, если от вывода зависит правка.
- `INFERRED` — выведена резолвером Graphify; подтверждай по коду.
- `AMBIGUOUS` — неоднозначная; подтверждай по коду.

`graphify-out/` коммитится в git, кроме локального `cost.json` (добавь `graphify-out/cost.json` в `.gitignore`). `cache/` — по желанию команды. Содержимое каталога изменяется только командами graphify — никогда вручную.

Грязные файлы в `graphify-out/` после hook или `update` ожидаемы. Грязный git status в этом каталоге — не повод игнорировать граф.

## 2. Подготовка перед анализом кодовой базы

**Шаг 1 — наличие графа:**

```bash
test -f graphify-out/graph.json
```

Если граф отсутствует:

- при наличии skill ассистента: `/graphify .`
- иначе через CLI, только код (локальный AST, без LLM): `graphify extract . --code-only`

Полный extract без `--code-only` имеет смысл, когда нужно проиндексировать docs/PDF/images и согласован backend. В PowerShell — `graphify .` без ведущего слэша.

**Шаг 2 — актуальность.** Не гоняй `check-update` перед каждым точечным вопросом. Обновляй заранее, если:

- только что был `git pull` / merge;
- в этой сессии уже меняли код;
- предыдущий query не видит файлы, которые точно есть на диске.

```bash
graphify check-update .
```

Если Graphify сообщает об изменённых или новых файлах:

```bash
graphify update .
```

**Шаг 3 — обзор только для архитектуры.** Для общего понимания системы читай `graphify-out/GRAPH_REPORT.md`. Если есть `graphify-out/wiki/index.md`, используй wiki для навигации по подсистемам. Для точечного вопроса («где вызывается X», «как A связано с B») сразу переходи к разделу 3 — не читай отчёт целиком.

## 3. Query-first workflow

Для вопросов о кодовой базе сначала обращайся к графу, а не к grep или обходу файлов.

| Задача | Команда |
| --- | --- |
| Общий вопрос на естественном языке | `graphify query "<вопрос>"` |
| Разбор конкретного класса, функции, модуля, таблицы | `graphify explain "<Concept>"` |
| Как связаны две сущности | `graphify path "<A>" "<B>"` |

Что возвращают команды:

- `query` — scoped-подграф, релевантный вопросу (по умолчанию BFS; `--dfs` — одна цепочка; `--budget N` — лимит токенов);
- `explain` — узел: файл и строка источника, сообщество, степень, связи с тегами достоверности;
- `path` — кратчайшая цепочка связей между двумя сущностями (hop за hop'ом, с типами рёбер).

Если Graphify MCP уже запущен, можно использовать его инструменты:
`query_graph`, `get_node`, `get_neighbors`, `shortest_path`
(для обзора ещё `god_nodes`, `graph_stats`, `get_community`).

Не поднимай MCP «на всякий случай». Команда сервера:

```bash
python -m graphify.serve graphify-out/graph.json
```

После `graphify update` CLI читает новый `graph.json` сразу. MCP-сервер держит граф в памяти со старта и **не** подхватывает обновление, пока процесс не перезапущен. При сомнении в свежести используй CLI.

**Fallback на `rg`, поиск IDE и прямое чтение файлов разрешён**, когда:

- запрос к графу не дал достаточного результата;
- нужен точный текст кода: сигнатуры, реализация, тесты;
- граф отсутствует и построить его сейчас невозможно.

**Запрещено:** начинать архитектурный анализ с полного обхода файлов или широкого grep при доступном актуальном графе; отвечать на архитектурные вопросы только по памяти.

## 4. Верификация по исходному коду

Граф — инструмент навигации и поиска связей. Окончательный источник истины — исходный код и тесты.

После того как граф указал релевантные узлы и файлы:

1. прочитай соответствующие исходники;
2. проверь сигнатуры и реальные call sites;
3. проверь тесты;
4. связи `INFERRED` и `AMBIGUOUS` подтверждай по коду, прежде чем опираться на них в выводах;
5. даже `EXTRACTED` сверяй по коду, если вывод влияет на правку, контракт или runtime (динамические вызовы, DI, конфиг, условные ветки AST не закрывает).

Вывод графа не является достаточным подтверждением точного runtime-поведения: порядок вызовов, условия, конфигурация и динамическая диспетчеризация видны только в коде и тестах.

## 5. После изменений кода

Если были созданы, изменены или удалены файлы с кодом:

```bash
graphify update .
```

Это AST-only обновление, без API. Успешный `update` уже пишет новый граф — повторный `check-update` после него не обязателен. Имеет смысл, только если update вернул ошибку или отказ записать граф.

`--force` нужен, когда ожидается **уменьшение** числа узлов — после удаления файлов, массового переименования или крупного рефакторинга. Shrink-guard отказывается перезаписывать граф меньшего размера без флага:

```bash
graphify update . --force
```

Эквивалент: `GRAPHIFY_FORCE=1`. Не используй `--force` без такой причины.

`--force` не лечит неполный прогон извлечения. Сообщение `extraction was incomplete … refusing to overwrite` — сначала устрани причину и перезапусти; `--allow-partial` только осознанно.

Обновление графа **не заменяет** тесты, lint, typecheck и build.

Опционально для проекта (по согласованию с пользователем): `graphify hook install` ставит post-commit / post-checkout хуки автообновления (локальный AST, без API) и merge driver, который объединяет `graph.json` при параллельных коммитах. Хуки не покрывают `git pull` — после pull по-прежнему нужен `graphify update .`.

Исключение файлов из индексации — через `.graphifyignore` в корне (синтаксис `.gitignore`, включая `!`-негации). `.gitignore` учитывается автоматически. Если есть оба файла, паттерны мержатся: `.graphifyignore` вычисляется последним и только сужает множество, не возвращая то, что уже исключил `.gitignore`. Не копируй весь `.gitignore` в `.graphifyignore`. Чтобы проиндексировать git-ignored сгенерированный код: `graphify extract . --no-gitignore` (`.graphifyignore` всё равно действует).

## 6. Политика LLM backend

**По умолчанию всё локально:**

- код парсится tree-sitter AST локально, без LLM и без сети;
- для обычной индексации и обновления кода **не передавай `--backend`**;
- для первого индекса кода предпочтителен `graphify extract . --code-only`;
- не запускай cloud backend автоматически, по собственной инициативе.

`--backend` — это выбор движка семантического прохода, не синоним «облака». `ollama` локальный; `openai` / `gemini` / `claude` / `azure` / `bedrock` отправляют данные во внешний endpoint.

Backend допустим только в трёх случаях:

1. semantic extraction документов, PDF или изображений (код в этом не нуждается);
2. повторное именование сообществ;
3. явное требование пользователя.

Примеры именования сообществ:

```bash
graphify label . --backend <b> --model <m>
graphify cluster-only . --backend <b> --model <m>
```

Ключи и endpoint'ы берутся только из окружения (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `OLLAMA_BASE_URL` и т.д.).

**Запрещено:** записывать API keys, access tokens и секретные endpoint credentials в `AGENTS.md`, этот файл или любые файлы репозитория; отправлять содержимое проекта внешнему LLM backend без явной необходимости и настроенного доверенного endpoint. Для чувствительных данных предпочитай `--backend ollama`.

## 7. Сводка запретов

- Не редактируй содержимое `graphify-out/` вручную.
- Не отвечай на архитектурные вопросы только по памяти, когда граф доступен.
- Не считай вывод графа достаточным подтверждением точного runtime-поведения.
- Не опирайся на связи `INFERRED` / `AMBIGUOUS` без подтверждения по коду.
- Не передавай `--backend` при обычной индексации кода и не запускай cloud backend автоматически.
- Не отправляй содержимое проекта внешнему LLM backend без явной необходимости и доверенного endpoint.
- Не записывай секреты в файлы репозитория.
- Не используй `--force` без причины из раздела 5.
- Не путай `--force` (меньше узлов после реального удаления) и `--allow-partial` (неполный extract).
- Не считай MCP свежее CLI после `update` без перезапуска сервера.

## 8. Краткий справочник команд

```bash
# построение и обновление
graphify extract . --code-only   # первый граф: локальный AST, без LLM
graphify extract .               # полный прогон (код + docs/PDF, если нужен semantic pass)
graphify update .                # инкрементальное обновление
graphify update . --force        # обновление при уменьшении числа узлов
graphify update . --no-cluster   # без рекластеризации (быстрее)
graphify check-update .          # проверить актуальность графа без записи

# запросы
graphify query "<вопрос>"        # scoped-подграф под вопрос
graphify explain "<Concept>"     # узел: источник, сообщество, связи
graphify path "<A>" "<B>"        # кратчайший путь между сущностями

# сообщества
graphify cluster-only .          # перекластеризация без переизвлечения
graphify label . --backend <b> --model <m>   # именование сообществ (LLM)

# прочее
graphify export callflow-html    # HTML с Mermaid-обзором архитектуры и call flow
python -m graphify.serve graphify-out/graph.json   # MCP stdio server
```

## 9. Типовые проблемы

- **Граф содержит меньше узлов после рефакторинга / «refusing to overwrite»** — shrink-guard: `graphify update . --force` (или `GRAPHIFY_FORCE=1`).
- **«extraction was incomplete … refusing to overwrite»** — прогон извлечения упал или прочитан не весь корпус; устрани причину и перезапусти. `--allow-partial` — только осознанно, с риском неполного графа.
- **Дубликаты узлов одной сущности** (граф собран старой версией graphify) — полное переизвлечение: `graphify extract . --force`.
- **`graph.html` слишком большой** (>5000 узлов, не открывается в браузере) — генерируй с `--no-viz` и работай через `graphify query` по `graph.json`.
- **`graphify: command not found`** — каталог инструментов не в `PATH`: `uv tool update-shell` или `pipx ensurepath`, затем новый терминал; либо `python -m graphify`.
- **MCP отвечает устаревшим графом после `update`** — перезапусти `python -m graphify.serve` или используй CLI.
- **Claude Code: инвалидация prompt cache** — записи в `graphify-out/` сбрасывают кэш. Рекомендация README Graphify: добавь в `.claudeignore` строки `graph.json` и `graphify-out/`.
